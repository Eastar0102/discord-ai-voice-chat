## 두 프로세스

![파이프라인](images/pipeline.svg)

| | Node.js (`discord_bot/`) | Python (`src/`) |
|---|---|---|
| 맡은 일 | 디스코드 게이트웨이, 음성 수신·재생, 텍스트 명령 | 듣기·생각·말하기·기억 전부 |
| 이유 | 디스코드 음성 수신은 `@discordjs/voice`가 가장 성숙했다 | Whisper·임베딩·LLM 생태계가 파이썬이다 |
| 연결 | WebSocket `/ws` (바이너리 = 오디오, 텍스트 = 제어 JSON) | REST (`/read`, `/look`, `/transcribe/*`, `/inspect/*`, `/llm/*`, `/tts/*`) |

Node 쪽은 거의 생각하지 않습니다. 화자 잠금(한 번에 한 사람 소리만 보냄), 재생 큐, 끼어들기 신호, 그리고 누가 채널에 있는지(`speaker`, `voice_event`)를 파이썬에 알려 주는 것이 전부입니다.

## 턴 하나의 일생

사람이 말을 시작해서 첫 소리가 나갈 때까지입니다. 코드는 `src/websocket_handler.py`에 있습니다.

```
 사람 말 ─┬─ 20ms PCM 청크 (48k 스테레오)
          │   → 안티앨리어싱 + 16k 모노
          │   → StreamingVAD (WebRTC + RMS)
          │
          ├─ 말하는 중 (0.5초마다)
          │    부분 전사 (Whisper) ──→ prefetch: 이 부분 문장으로 프롬프트를 미리 먹여
          │                                     LLM의 prefill 캐시를 데움
          │
          ├─ 말끝 판단 (먼저 오는 것)
          │    · early   — 침묵 시작 + 부분 전사가 문장부호로 끝남   (~0.3초)
          │    · silence — 침묵 600ms
          │    · stall   — 패킷이 0.4초 끊김 (이어질 말처럼 들리면 1.0초)
          │
          ├─ 최종 전사 — 부분 전사가 음성 구간을 다 덮었으면 재사용 (≈0초)
          ├─ 걸러내기 — 방송 환각 문구, 이름만 늘어놓은 소음
          ├─ 끊긴 발화 병합 — 앞 턴이 아직 생성 중이면 취소하고 텍스트를 이어 붙임
          │
          ├─ 말할 차례 (should_reply)
          │    always → 답함 / 이름 → 답함 / call → 안 답함
          │    auto: 혼잣말 신호 → 안 답함
          │          다른 사람 이름을 부름 → 안 답함
          │          둘뿐 → 답함 / 여럿 → 대화 중이거나 2인칭+질문일 때만
          │    + must_answer(이름·2인칭·질문 어미)가 아니면 LLM 판정을 나란히 시작
          │
          ├─ 이어질 말로 끝났으면 ("아니 근데") 1.2초 기다림 — 뒷말이 오면 병합
          │
          ├─ 프롬프트 조립 (llm.build_messages) — 기억·세계관 검색 포함
          ├─ LLM 스트리밍
          │    · 첫 14자: 최근 대답을 베꼈으면 한 번 다시 뽑음
          │    · 선두 감정 태그 → 이번 턴 TTS 스타일
          │    · 첫 조각 직전: 판정 결과 확인 (0.6초까지만 기다림) — 아니라면 여기서 접음
          │    · 괄호 지문·*행동* 제거, 목록·구분선이 나오면 거기서 끊음
          │
          └─ 문장이 끝날 때마다 TTS 큐 → 순서대로 합성 → WebSocket으로 오디오 + 자막
```

**끼어들기**: Node가 재생 중에 새 발화를 감지하면 `stop_audio`를 보냅니다. 파이썬은 생성 중인 스트림을 취소하고, TTS 큐의 대기 작업도 취소해 세마포어를 풉니다.

**턴 기록**: 실제로 말한 턴만 `turn` 이벤트로 남습니다. 판정이 접은 턴은 `gate`로 남습니다.

## 프롬프트 배치

`llm.build_messages()`가 매 턴 조립합니다:

```
[system]
  캐릭터 팩 prompt.txt
    $TOPIC  ← topic.txt (말투 예시)
    $MEMORY ← memory.retrieve_relevant_memory()  — 말하는 사람·자기·겪은 일·있었던 일
    $LORE   ← lore.retrieve_relevant_lore()      — 관련 블록 최대 2개
  [대화 공백] 또는 [이번 대화 앞부분]  ← 30분 넘게 끊겼으면 알림, 아니면 세션 요약
  [현재 상황]   ← 서버·채널, 들어온 시각, 사람별 "지금 있음" 표, 최근 나간 사람, 활동 상태
  [지금 보고 있는 것]  ← 기사·화면·문서 (있을 때만, TTL 30분)
  [화자 정보]   ← 만든 사람인지 (identity.owner_names)
  [현재 시각]   ← 맨 끝. 날짜를 물으면 이 줄을 그대로 읽으라는 지시 + 형식 한 줄
[history]  최근 20줄 — 출력 형식으로 정규화, 지난 세션은 6줄까지, 중복 대답 제거
[user]     "[화자 이름] 발화"
```

**`cache_layout`** (llama.cpp provider에서 켜짐): 턴마다 바뀌는 칸(기억·세계관·상황·시각)을 기록 *뒤*의 두 번째 system 메시지로 옮깁니다. 그러면 앞부분이 매 턴 같아서 prefill 캐시가 살아남습니다. 실측으로 첫 토큰이 2.6초에서 1.6초로 줄었습니다. 기록 창도 10줄 단위로만 밀어 앞부분을 고정합니다.

## 기억의 일생

코드는 `src/memory.py`에 있습니다.

```
대화 기록 (data/characters/<id>/conversation_history.jsonl — 캐릭터마다 따로)
   │  유휴 5분 · 봇 퇴장 · 사람 발화 20줄
   ▼
flush_episode()
   │  Whisper 확신도 낮은 줄 제외
   ▼
extract()  ── 요약 모델 (기본: 대화 모델, format=json)
   │  episode / person_facts / self_said / self_experience
   │  + 사람마다 그 사람 말만 주고 한 번 더 (한 번에 뽑으면 사람을 통째로 빠뜨림)
   │  + 상대 날짜 → 절대 날짜, 앞일이면 due
   │  + 낱말 필터 (봇 작업·대화 자체·1인칭 인용·능력 부정)
   │  + 선택: screen — 후보를 대화와 나란히 다시 보여 주고 주제 분류 (life만 남김)
   ▼
_reconcile()  ── 그 사람의 기존 사실과 나란히: add / replace(old) / skip
   ▼
ChromaDB 컬렉션 memory_<캐릭터 id>
   metadata: type(episode|person|self), who(디스코드 ID | "self"), name, ts, due, kind(state|experience), about(주제)
```

**불러올 때**는 `retrieve_relevant_memory()`가 다음을 고릅니다:

| 칸 | 고르는 법 |
|---|---|
| 주제 | 이번 말이 `memory.topics`의 주제에 걸리면 그 주제 기억을 가까운 순으로 |
| 말하는 사람 | 검색 없이 늘. 8칸 = 관련 5 + 최근 3. 날짜 지난 일정은 맨 위 "먼저 챙길 것"으로 |
| 자기 설정 | 늘. "말을 바꾸지 말 것"을 붙임 |
| 겪은 일 | 최근 3 + 관련 1. "말을 바꾸지 말 것"은 붙이지 *않음* (지난 일을 지금 일로 우김) |
| 있었던 일 | 시간 표현("어제", "지난번") + 가장 최근 1 + 관련(거리 120 이내) |

## 백그라운드 루프

연결마다 `handle_connection`이 넷을 띄웁니다:

| 루프 | 주기 | 하는 일 |
|---|---|---|
| `stall_watchdog` | 0.1초 | 패킷이 끊기면 발화 강제 확정 |
| `memory_watchdog` | 10초 | 세션 요약 갱신, 조건이 되면 에피소드 저장 (대화 중에는 안 함) |
| `initiative_watchdog` | 5초 | 조용한 시간이 `기본 / (1 + 관심) × backoff^시도`를 넘으면 먼저 말함 |
| `manuscript_watchdog` | 20초 | 구글 문서가 바뀌었는지 보고 글쓰기 상태 전환, 조건이 되면 한마디 |

서버 시작 때는 LLM·TTS 워밍업과 `memory_manager.wake_up()`이 함께 돕니다. 입장 인사는 워밍업이 끝날 때까지 최대 45초 기다립니다.

## 관측 — metrics.jsonl

`data/metrics.jsonl`에 한 줄씩 쌓입니다. 컨트롤 앱의 대화·상태 탭이 이걸 읽습니다.

| event | 내용 |
|---|---|
| `turn` | 화자, 발화, 대답, 모델, `endpoint_s`·`stt_s`·`llm_first_s`·`tts_first_s`·`total_s`, STT 확신도 |
| `ttfa` | 첫 오디오가 나간 시각 (체감 지연 = endpoint + ttfa) |
| `gate` | 답했는지, 이유, 모드, 사람 수 |
| `spoke` | 먼저 꺼낸 말 (인사, 먼저 말 걸기, 원고 한마디) |
| `initiative` · `activity` · `look` · `read` · `manuscript` | 각 기능의 결정 기록 |
| `stt_timeout` · `stt_skipped` · `memory_error` · `name_noise` | 문제가 생긴 순간 |

판단을 하는 코드는 그 판단을 이유와 함께 남깁니다. 남기지 않은 게이트가 몇 달 동안 한 번도 작동하지 않았는데 아무도 몰랐던 일이 있어서입니다.

## 확장하기

### 새 provider 추가

인터페이스는 `src/providers/base.py`에 셋 있습니다:

```python
class STTProvider:  def transcribe(self, audio_np) -> str
class LLMProvider:  def chat(self, messages) -> str
                    async def stream_chat(self, messages, options=None) -> AsyncIterator[str]
class TTSProvider:  def synthesize(self, text, style="neutral") -> bytes | None   # WAV 바이트
```

1. `src/providers/<종류>/<이름>.py`에 구현합니다. 생성자는 `options: dict`(config의 같은 이름 섹션)를 받습니다.
2. `src/providers/<종류>/__init__.py`의 `get_provider`에 이름을 등록합니다.
3. `config.json`에 `"<이름>": {...}` 섹션을 만들고 `provider`를 그 이름으로 바꿉니다.

선택 메서드를 구현하면 더 붙습니다:

| 메서드 | 효과 |
|---|---|
| `warmup()` | 서버 시작·모델 교체 때 미리 로드 |
| `release()` | 다른 모델로 바꾸거나 전사 모드가 VRAM을 쓸 때 내려놓음 |
| `prefetch(messages)` | 말하는 중 프롬프트를 미리 먹여 캐시를 데움 |
| `cache_layout = True` | 턴마다 바뀌는 칸을 기록 뒤로 보내는 배치 |
| `slots > 1` | 판정·기억 호출을 대화와 다른 슬롯으로 |
| STT의 `set_names(names)`, `last_stats` | 채널 사람 이름 핫워드, 확신도 기록 |

### 새 명령·기능

- 텍스트 명령은 `discord_bot/index.js`에 추가합니다. 파이썬 기능은 `src/api_server.py`에 REST로 열고, Node에서 `axios`로 부릅니다.
- 프롬프트에 새 칸을 넣으려면 `llm.build_messages()`의 `add(블록, volatile)`을 씁니다. 턴마다 바뀌는 칸이면 `volatile=True`로 둬야 `cache_layout`에서 기록 뒤로 갑니다.

## 다른 언어로 바꾸려면

파이프라인은 그대로 두고, 한국어에 묶인 곳만 고치면 됩니다:

| 곳 | 무엇 |
|---|---|
| 캐릭터 팩 | `prompt.txt`, `topic.txt`, `lore.txt`, 호출어 |
| `websocket_handler.py` | `_SECOND_PERSON_RE`, `_MUST_ANSWER_RE`, `_SOLO_RE`(혼잣말), `UNFINISHED_WORDS`/`UNFINISHED_END_RE`(이어질 말), `FIRST_CLAUSE_RE`, 감정 단어 매핑 |
| `llm.py` | 시스템 지시문들(화자 정보·현재 시각·판정 프롬프트와 예시), `_STYLE_KO` |
| `memory.py` | 추출·갱신·분류 프롬프트, 날짜 표현(`_WEEK_RE`, `_REL_DAY` …), 필터 정규식 |
| 설정 | `stt.whisper_local`의 언어, `transcribe.defaults.language`, Edge TTS 목소리, 임베딩 모델(`vector_db.py`의 `jhgan/ko-sroberta-multitask`) |

## 설계 메모 — 틀리기 쉬운 것들

코드의 주석에는 각 결정이 어떤 실패를 고친 것인지 측정과 함께 남아 있습니다. 그중 다른 프로젝트에도 통할 것들입니다:

**말할 차례**
- **말할지 말지를 페르소나 모델에게 묻지 않는다.** 대답 안에 `(pass)`를 쓰라고 시켜 봤지만 실사용 286발화에서 0번 작동했습니다. 긴 성격 프롬프트가 그 지시를 이깁니다.
- 성격을 벗긴 Y/N 판정은 반대로 실패합니다. 조용해야 할 때 조용했지만, 답해야 할 말 100개 중 14개를 삼켰습니다.
- 그래서 규칙이 먼저입니다. 가장 센 신호는 사람 수입니다. 둘뿐일 때는 실제 기록 489발화 중 삼켜야 할 것이 1개였습니다.
- 판정은 규칙이 넘긴 것만 보고, 이름·2인칭·질문 어미에는 아예 묻지 않습니다.
- **기록으로는 한쪽 오류만 잴 수 있다.** 기록에 남은 말은 전부 대답한 것이라, 잘못 *침묵*하는 규칙은 기록으로 검증되지만 잘못 *대답*하는 쪽은 실제 세션에서만 보입니다.

**스트리밍과 지연**
- **Whisper는 전용 스레드 하나로 직렬화한다.** `asyncio.wait_for`는 퓨처만 취소하고 스레드는 계속 돕니다. `async with lock` 안에서 타임아웃이 나면 락이 풀리고, 다음 전사가 겹쳐 돌고, 그때부터 전부 느려져 연쇄로 시간 초과가 납니다.
- **디스코드는 말이 끝나면 침묵 패킷을 0.5초쯤 더 보내다 끊는다.** 그래서 "침묵 600ms" 규칙은 대개 채워지지 않습니다. 패킷 끊김(stall)을 따로 봐야 합니다.
- **TTS는 문장 끝에서만 자른다.** 첫 소리를 당기려고 문장 중간을 자르면 조각마다 억양이 새로 시작해 이음매가 다 들립니다.
- **GPT-SoVITS에 동시 요청을 보내지 않는다.** 셋을 동시에 보내면 14자 합성이 1.1초에서 13~30초로 늘었습니다.
- **로컬 LLM 벤치마크는 실제 provider로 잰다.** 요청의 `num_ctx`가 상주 모델과 다르면 Ollama가 모델을 다시 올리고, 그게 있지도 않은 지연으로 측정됩니다.

**프롬프트**
- **대화 기록은 형식 예시다.** 작은 모델은 규칙보다 직전 몇 턴의 모양을 따라 합니다. 지난 대답은 출력 형식 그대로 정규화해서 다시 넣습니다. 태그를 떼고 넣었더니 긴 세션에서 태그 준수가 0으로 떨어졌습니다.
- **현재 시각은 맨 끝에.** 중간에 두면 기억에 붙은 날짜에 끌려 하루씩 틀렸습니다 (4/8). 맨 끝으로 옮기자 12/12였습니다.
- **기록에 넣을 말과 모델에게 줄 말을 나눈다.** "(잠시 아무도 말하지 않음)"을 그대로 주면 "대화가 멈춰 있네요"라고 답합니다. "(네가 먼저 말을 꺼낸다)"를 주면 진짜 화제를 꺼냅니다.
- **채널에 막 들어왔을 때는 기록을 주지 않는다.** 주면 몇 시간 전 대화의 마지막 줄에 대꾸하며 입장합니다.

**기억**
- **낱말 필터는 그것을 쓴 날의 어휘만 잡는다.** 한 세션에 맞춰 쓴 목록이 다음 세션에서 저장된 엉뚱한 사실 30개 중 0개를 걸렀습니다. 일반화하려면 대화를 함께 보여 주고 "무엇에 관한 문장인가"를 묻는 판정이 필요합니다.
- **판정을 "버릴까?"로 물으면 진짜 사실을 깎는다.** 같은 모델이 "사소하다"며 20개 중 6~9개를 버렸습니다. "무엇에 관한 것인가"만 물으면 과잉이 1~2개로 줄었습니다.
- **판정할 모델이 없으면 덜 기억한다.** 확신도가 낮은 줄은 빼고, 에피소드당 한 사람 사실 수에 상한을 둡니다.
- **임베딩 거리로는 갱신을 못 잡는다.** "골드 2" → "플래티넘"은 거리 137이라 다른 사실로 둘 다 남았습니다. 모델에게 기존 사실과 나란히 보여 주고 고르게 합니다.
- **핫워드는 소음을 그 단어로 바꾼다.** 이름 두 개 이상으로만 된 전사는 버립니다. 이름 하나는 진짜 부르는 말일 수 있어 남깁니다.
- **"작업 중 끝난 일"과 "앞으로의 일정"을 가른다.** 말한 날 *당일*의 날짜를 일정으로 치면, 그날 있었던 일이 전부 "날짜가 지난 일정"이 되어 다음 인사가 "그거 어떻게 됐어요?"가 됩니다.
